# Programmatic SEO Pattern Library

Use this only after `programmatic-seo.md`. These are query-pattern candidates, not a recommendation to manufacture all of them.

| Pattern | Query formula | Best fit | Mandatory page-level value | Typical conversion path |
|---|---|---|---|---|
| Curation | best/top [category] | decision-stage category search | transparent criteria, fresh dataset, decisive recommendation | product category CTA |
| Comparison | [x] vs [y], [x] alternatives | late-stage evaluation | current attributes, pricing/proof, “who each is for” | switch/trial/demo |
| Use case | [product/category] for [audience] | persona-specific buying | audience-specific workflow, proof and objections | tailored signup/demo |
| Integration | [tool] + [tool] | interoperability intent | real setup steps, limits, screenshots, outcome | connect/install/signup |
| Template | [type] template/generator | task completion | usable asset in-browser, examples, instructions | product-assisted use |
| Converter | [x] to [y] | repeat utility | reliable conversion/tool behavior | repeat use/adjacent tools |
| Examples | [type] examples | research/inspiration | curated real examples, taxonomy/filters, analysis | create/build CTA |
| Directory | [category] tools/software | broad discovery | maintained entities, useful attributes/filters | listing/product selection |
| Glossary | what is [term] | educational/entity | precise definition, examples, related concepts | internal authority path |
| Localization | localized [query] | non-English/local market | localized intent, examples, units, regulations/culture | localized product path |
| Location | [service] in [place] | local discovery | real local inventory/data and useful differentiation | booking/contact |
| Profile | [entity] + [attribute] | entity research | original/verified attributes, timelines, relationships | related product/content |

## Pattern selection scorecard

Score each candidate 0–2:

1. **Demand repeatability** — no repeated shape / weak / clearly validated.
2. **Data uniqueness** — token swap / some page-specific data / strong unique utility.
3. **Intent fit** — mismatched / mixed / exact SERP match.
4. **Conversion relevance** — remote / indirect / clear product path.
5. **Maintainability** — no owner / manual burden / sustainable pipeline.
6. **Differentiation** — raw-source clone / modest synthesis / hard-to-copy value.

Do not build a system below 9/12, and never override a zero on data uniqueness or intent fit.

## Layering gate

Layer two patterns only when all are true:

- combined query examples exist in live data or SERPs
- the combined page answers a meaningfully narrower intent
- data exists for both dimensions
- the page is not near-duplicate of either parent family
- projected pages are deduplicated and capped
- one-pattern cohort already passes quality/indexation checks, unless the layered family itself is the smallest viable test

Examples to investigate, not assume:

- curation × location
- comparison × use case
- integration × audience
- glossary × locale
- directory × niche

## Unique-data ledger

Create one row per dynamic field:

| Field | Source | Page-specific? | Freshness | Validation | User value | Missing-data behavior |
|---|---|---:|---|---|---|---|

A page cannot publish if its mandatory page-specific fields are missing. Never ask the language model to fill factual gaps.

## Cohort launch template

- **Cohort 0 — prototypes:** 5–20 pages; manual QA, intent match, data integrity, template usability.
- **Cohort 1 — validation:** enough pages to test crawl/indexation and impressions without flooding the site.
- **Cohort 2 — expansion:** only after quality, indexation, ranking movement and operational refresh are credible.
- **Cohort 3 — scale:** automate generation/updates; keep hard quality thresholds and pruning rules.

Exact cohort sizes depend on site authority, crawl capacity, demand, and quality. Do not use a universal publish count.

## AI-answer readiness

For pages targeting answer-engine visibility, add citation-ready structure without writing for robots:

- answer the core query plainly
- state who the option/page is for
- keep attributes and comparison fields explicit
- cite material facts and show freshness
- add first-party evidence or utility
- make each major section understandable on its own

Measure AI visibility separately. Do not promise citation simply because a page ranks.
